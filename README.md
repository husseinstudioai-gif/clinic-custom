# Clinic Custom — سامانه مدیریت کلینیک زیبایی

نسخه شروع (starter) برای مدیریت چندکاربره کلینیک با رابط فارسی و راست‌چین. این پروژه شامل رابط وب HTML/CSS/JavaScript و سرور Node.js/Express با پایگاه‌داده SQLite است.

## امکانات فعلی
- ورود و خروج با نشست سمت سرور، هش رمز عبور با bcrypt و محدودسازی تلاش ورود
- نقش‌های مدیر، پذیرش، پزشک، امور مالی و آزمایشگاه
- پرونده بیماران، نوبت‌دهی، امور مالی، دستورات پزشک، آزمایشگاه و بیمه
- داشبورد، جست‌وجوی رکوردها، ویرایش و چاپ / ذخیره گزارش به PDF
- ساخت کاربران توسط مدیر و ثبت رویدادهای امنیتی
- طراحی واکنش‌گرا برای موبایل و دسکتاپ

## نیازمندی‌ها
- Node.js نسخه 20 یا بالاتر
- npm

## اجرای محلی
1. پوشه پروژه را استخراج کنید.
2. در پوشه پروژه، وابستگی‌ها را نصب کنید:
   ```bash
   npm install
   ```
3. فایل `.env.example` را به `.env` تبدیل کنید و `SESSION_SECRET` و رمز مدیر را به مقادیر قوی و منحصربه‌فرد تغییر دهید.
4. متغیرهای محیطی را در ترمینال تنظیم کنید. Node.js به‌تنهایی فایل `.env` را در همه نسخه‌ها/تنظیمات بارگذاری نمی‌کند؛ برای اجرای ساده می‌توانید از `node --env-file=.env server.js` در Node 20.6+ استفاده کنید.
5. سرور را اجرا کنید:
   ```bash
   node --env-file=.env server.js
   ```
6. در مرورگر به `http://localhost:3000` بروید.

در اولین اجرا، حساب مدیر در پایگاه‌داده ساخته می‌شود. نام کاربری و رمز را از متغیرهای محیطی تنظیم کنید. اگر پایگاه‌داده از قبل ساخته شده باشد، تغییر متغیرهای bootstrap رمز موجود را تغییر نمی‌دهد؛ برای تغییر رمز باید قابلیت مدیریت/بازیابی رمز را به‌صورت امن پیاده‌سازی کنید یا در محیط توسعه پایگاه‌داده آزمایشی را حذف و دوباره ایجاد کنید.

## استقرار روی سرور
1. از VPS یا میزبانی Node.js استفاده کنید؛ میزبانی استاتیک صرفاً HTML مثل GitHub Pages یا Netlify به‌تنهایی برای این نسخه کافی نیست.
2. دامنه و HTTPS را از طریق یک reverse proxy مانند Nginx یا سرویس میزبانی معتبر فعال کنید.
3. `NODE_ENV=production`، `SESSION_SECRET` قوی و `ADMIN_PASSWORD` قوی تنظیم کنید.
4. فقط از طریق HTTPS دسترسی دهید؛ در حالت production کوکی نشست `Secure` می‌شود.
5. برای چند نمونه سرور، SQLite و نشست حافظه‌ای پیش‌فرض کافی نیستند. از PostgreSQL و ذخیره‌ساز نشست مشترک (مثلاً Redis) استفاده کنید.
6. پشتیبان‌گیری خودکار و رمزگذاری‌شده، محدودیت دسترسی به فایل پایگاه‌داده، پایش خطا و روند بازیابی را آزمایش کنید.

## مدل دسترسی
- مدیر: تمام بخش‌ها، ساخت کاربران، حذف رکوردها و گزارش رویدادهای امنیتی
- پذیرش: بیماران، نوبت‌ها، بیمه و گزارش‌های مجاز
- پزشک: بیماران، نوبت‌ها، دستورات پزشک، آزمایشگاه و گزارش‌های مجاز
- امور مالی: مالی، بیمه و گزارش‌های مجاز
- آزمایشگاه: بیماران، آزمایشگاه و گزارش‌های مجاز

## هشدارهای مهم پیش از استفاده واقعی
این پروژه یک نمونه شروع قابل اجراست، نه نرم‌افزار پزشکی تأییدشده یا آماده استفاده بالینی. پیش از واردکردن اطلاعات واقعی بیماران:
- مدیریت رضایت بیمار، سیاست نگهداری/حذف اطلاعات، کنترل دسترسی دقیق‌تر به هر پرونده و ثبت مشاهده پرونده را تکمیل کنید.
- رمزنگاری در حالت سکون، مدیریت کلیدها، پشتیبان رمزگذاری‌شده و آزمون بازیابی را پیاده‌سازی کنید.
- بررسی امنیتی مستقل، آزمون نفوذ، کنترل‌های قانونی و الزامات محلی حفاظت از داده‌های سلامت را انجام دهید.
- سرور نشست پیش‌فرض Express در حافظه است و برای production یا چند نمونه سرور مناسب نیست؛ از session store پایدار استفاده کنید.
- CSRF protection، گردش کار بازیابی/تغییر رمز، MFA و مدیریت غیرفعال‌سازی نشست‌ها باید پیش از استقرار واقعی اضافه شوند.
- اطلاعات فعلی در SQLite به شکل JSON متنی ذخیره می‌شوند و در این نسخه رمزنگاری پایگاه‌داده پیاده نشده است. این نسخه را برای داده‌های شناسایی‌پذیر واقعی بیماران در محیط عملیاتی استفاده نکنید.

## نسخه دارای تصویر کاربران و فونت فارسی
- در بخش «مدیریت کاربران»، هنگام ساخت حساب می‌توانید تصویر JPG/PNG/WebP اضافه کنید؛ تصویر کوچک و در پایگاه داده محلی ذخیره می‌شود.
- تصویر حساب کنار نام کاربر در سربرگ و فهرست کاربران نمایش داده می‌شود.
- متن‌های عادی از فونت Vazir/Vazirmatn استفاده می‌کنند و عنوان‌ها ابتدا فونت Titr را از فونت‌های نصب‌شده سیستم می‌گیرند. برای نمایش دقیق Titr، فونت Titr را در ویندوز نصب و مرورگر را دوباره باز کنید. در صورت نبود فونت، از فونت جایگزین استفاده می‌شود.
- پیش از ارتقا از پوشه پروژه و فایل `clinic-custom.sqlite` نسخه پشتیبان تهیه کنید. این نسخه با اضافه کردن ستون `avatar_data`، پایگاه داده موجود را به‌صورت خودکار ارتقا می‌دهد.
